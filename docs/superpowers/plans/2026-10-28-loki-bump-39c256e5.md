**Goal:** Move the pinned Loki commit from `bc1962860a1607eccb7e0c8ee206970b292b9e80` (2026-10-12) to the current `main`, `39c256e50a804c045d5eb4e3c817a31653b535fe` (2026-10-27). This brings in Loki's regex-simplifier fix (#25413) and the other LogQL fixes since the pin. lokihouse's push metrics and push error behaviour stay as they are.

**Architecture:** One compatibility break: Loki removed `push.ParseRequest` (#24739). Its logic moved into the unexported `(*Distributor).pushHandler`/`recordParsedRequest`, and its Prometheus collectors moved from `pkg/loghttp/push` package variables into the distributor's `metrics` struct. lokihouse does not construct a distributor. It gets a small copy of the parse-and-record part, plus its own package-level collectors under Loki's exact metric names. Every other change is a pin update. The copied Loki functions are byte-identical at both commits (verified 2026-10-28), so their headers only change the SHA.

**Tech Stack:** Go 1.27.3 (`go` directive moves 1.27.1 → 1.27.3, which matches the existing `toolchain`, `Dockerfile` `GO_VERSION` and `debian/rules`), Loki `pkg/loghttp/push`, Prometheus client_golang.

**Spec:** No separate spec file. Findings from the trial bump on 2026-10-28 (worktree, reverted):
- `go get github.com/grafana/loki/v3@39c256e5…` plus `go mod tidy`: the only build error is `internal/ingest/handler.go:51: undefined: push.ParseRequest`.
- With that call replaced, `go build`, `go vet ./...` and `go vet -tags oracle,bench ./test/...` are clean. `go test ./...` passes except `TestRun_Metrics`: `loki_distributor_lines_received_total` is no longer registered.
- Loki's `go.mod` replaces that changed: `azblob` v1.8.0 → v1.8.2, `thanos-io/objstore` → `github.com/grafana/objstore v0.0.0-20261013190022-d05e3fae91a4`, and `pkg/push` follows the pin (`v0.0.0-20261027220337-39c256e50a80`).
- Upstream behaviour lokihouse inherits through Loki's engine and parser:
  - #25567: Kahan summation in `sum`, `avg`, `sum_over_time`, `avg_over_time`, and unwrapped `rate`/`bytes_rate`.
  - #25413: `|~ "a .*(bb|cc)"` no longer simplifies wrongly.
  - #25795: `|~ ".*"` / `"(?i)"` count as no filter.
  - #25168: `HasFilter` checks the whole chain. lokihouse uses it only in `internal/deletes/handler.go` to decide whether to validate the shard interval.
  - #25427: stream-first queries fail on the first pipeline error.
  - #25091: rename-on-clash ignores dropped labels.
- lokihouse's own SQL sums are integer (counts and bytes), so Kahan summation does not create a pushdown difference. The oracle (relative tolerance 1e-9) is the proof.
- Not fixed upstream: `newOrFilter` drops `TrueFilter` legs (`foo|.*` filters as `contains("foo")`), unchanged on `main`.
